# BREATH / Speech-intention Avatar Prototype

**研究用の最小デモ**: 人間1人とAIアバター1体の音声対話で、LLMが内容依存の「発言したい」意思を生成すると、AIが**吸気モーション**で発話希望を予告し、人間の反応によって話す／延期／撤回する。

![Technical status](https://img.shields.io/badge/stage-research%20prototype-blue)

## 起動方法（Windows PowerShell / macOS / Linux）

Node.js 20 以降を用意してください。依存パッケージのインストールは不要です。

```powershell
# ZIPを展開したディレクトリで
copy .env.example .env
# テキストエディタで .env を開き GEMINI_API_KEY=... を設定する（LLMモードのみ）
npm start
```

ブラウザで **http://127.0.0.1:3977/** を開きます。実験者の操作画面は **http://127.0.0.1:3977/operator** です。参加者向けの余計なラベルを隠す表示は **http://127.0.0.1:3977/?participant=1** です。

- Gemini APIキーを利用する場合、[Google AI Studio](https://aistudio.google.com/apikey) で発行したキーを `.env` の `GEMINI_API_KEY=` の右に設定します。
- `.env` を変更したらサーバーを再起動します。APIキーはブラウザ側へ出さず、ローカルサーバーからGoogleへ送ります。
- Geminiのモデルは既定で `gemini-3.5-flash-lite`。必要なら `.env` で変更できます。
- APIキーを設定しなくても、**操作デモ**でモーション・TTS・操作ログを試せます。

## まず体験するなら

1. 起動して参加者画面を開く。AIは待機姿勢をしています。
2. 手動確認なら、別タブで `/operator` を開く。
3. 実験者画面で「① 吸気して発話希望を示す」をクリックする。胸・肩・頭が上がる吸気モーションが起こり、AIが待つ状態に移ります。
4. 参加者画面で「話していいよ」を押すと音声で発言します。「ちょっと待って」で延期、「撤回」でキャンセルできます。
5. LLMモードを試す場合はAPIキーを設定後、参加者画面で「LLM 自発」を選び、必要なら「AIの積極性」を調整し、マイクを開始して**一つの話題について長めに話す**。ブラウザの文字起こしからGeminiが独自の質問・指摘を考えたときに吸気動作します。
6. マイクが認識されない場合、右側のテキスト欄に人間の発話途中の文章を入力して「入力内容をLLMに判定させる」を押すこともできます。
7. 「JSON出力」で合図、発話、延期、撤回、LLMの判断理由などの時系列ログを保存できます。

## アーキテクチャ

```text
マイク → ブラウザ SpeechRecognition（中間文字起こし）
      → ローカル Node.js /api/analyze → Gemini（発話希望の内容判断）
                                       ├ 発話不要 → 聞き続ける
                                       └ 発話希望 → 吸気モーション
                                                     ↓
       参加者のボタン / ブラウザRMS音量判定 → 発話・延期・撤回
                                                     ↓
                                    SpeechSynthesis 日本語読み上げ
```

- **Gemini** は「今、発言したい具体的理由があるか」「何を話したいか」を判断します。
- **身体的合図**はSVG + CSSで肩・胸・頭・口・吸気流線を動かします。顔写真や外部3Dモデルには依存しません。
- **発話時刻**は参加者操作とブラウザの音量RMS検出による簡易制御です。MaAIではありません。
- **参加者向け画面**は `?participant=1`。研究者の評価説明や内部判断、操作パネルを隠し、アバターとマイクだけを見せられます。
- **手動/実験者制御**は同一ローカルサーバーのSSE（Server-Sent Events）で参加者画面に届きます。

## 現時点でできないこと・研究上の注意

- この版は **MaAI/VAPを組み込んでいません**。MaAIは発話活動・交替の予測が主で、会話内容からLLMの発話希望を生み出すものではないため、役割を分けています。[MaAI公式リポジトリ](https://github.com/MaAI-Kyoto/MaAI)
- ブラウザのWeb Speech APIはブラウザ依存です。Chrome/Edge推奨。SpeechRecognitionはブラウザの音声認識サービスを利用する場合があり、音声データは完全なローカル処理を保証しません。
- GeminiのAPIを使用すると、文字起こしテキストがGoogle APIに送信されます。研究参加者へ事前説明し、同意を得てください。
- LLMは各スナップショットの部分文字起こしを解析しているだけで、**人間の発話意図・譲渡意思を直接測定していません**。
- 発話タイミング用のRMS閾値はヒューリスティックです。静かなマイク、環境騒音、長音、TTSの音声への反応などでは誤判定し得ます。
- 人間の発話を妨げた効果と、実際に主体性や信頼が高まった効果は区別してください。小規模デモではそれらを因果的に検証できません。
- 手動実験はWizard-of-Ozであり、**LLMが自発的に意図を生成したとは主張できません**。
- `responseSchema`のサポートやモデルの利用可能性はAPI契約やモデル更新で変わる場合があります。エラーはイベントログに出ます。
- 現バージョンは1人の参加者を想定したローカルデモです。サーバーは `127.0.0.1` のみにバインドしています。
- キーは共有しないでください。`.env` は `.gitignore` で除外しています。

## 次の段階

1. 少人数で吸気の見え方・発話意思の解釈・不快感を観察。
2. 意味依存の自発的発話意図と、手動／ランダムな合図を分けて比較できるよう制御。
3. 必要が明確になった段階で MaAI から発話活動予測を読み込み、人間の継続・譲渡に応じる制御を置き換える。
