# 2 体の AI の話し合い：技術評価（途中経過、2026-11-15）

対象は bb825cf の two_ai。研究計画 v2 の §6.4 の評価項目のうち、合成音声で測れるものを測った。**途中経過である。** 追加の測定（2 体の描画＋nice 15、描画なしの ① の追加 2 本、2 体の ②、実 API の ① と ② の各 1 本）は、この文書を書いた時点でまだ走っている。

## 読み方
- 数値はすべて WSL2 のヘッドレス Chromium（ソフトウェア描画 SwiftShader）、16 コア、実 MaAI（CPU、torch 4／ONNX 4）での値。**Windows の Chrome（GPU）の値ではない。**
- 本人役の声は Gemini TTS の合成音声だけ（声 Kore）。実在の人の声は使っていない（台本の TTS の声も ElevenLabs の合成音声に差し替えた。models/ja.wav は使っていない）。
- 台本の LLM／STT／TTS（test_double）での値なので、生成と STT の遅れは含まない。停止の経路（ブラウザ → WS → MaAI → 進行役 → 語の境界での停止 → ブラウザの再生停止）は本物。

## 方法
道具：`tools/two_ai_eval/`（新規）
- `synth_voices.mjs`：本人役の合成音声を作る（Gemini TTS、計 14 回の呼び出し。相づち 4、発言 6、intake 4）。
- `stimuli.ts`：偽マイクの WAV を作る。intake は 3／14／26／42 秒に文、80 秒からは 11〜19 秒おきに、中身のある発言・相づち（うん、はい、うんうん、なるほど）・咳に似た雑音（帯域を絞った雑音の破裂 2〜3 回、約 -18 dBFS）・息（強 -34 dBFS／弱 -50 dBFS）を種つきの乱数で置く。-70 dBFS の雑音の床を敷く。台本の STT の区切りを真似て、声でない音の区間には文を返さない（''）。
- `run.ts`：e2e と同じ経路（Next、ヘッドレス Chromium、偽マイク、OrchestratorServer、実 MaAI）を、ポート 3482／8808 で回す。`SAVE_SESSION_AUDIO=1` で 2ch の録音（ch1 = マイク、ch2 = ワークレットが出力に書いた AI の音）を残す。`--query avatar_a=none&avatar_b=none` で描画なし、`--nice` でブラウザのプロセス木を renice、`--real` で実 API。
- `analyze.ts`：録音とログを突き合わせる。
  - **止まるまでの遅れ**＝録音の ch1 で刺激の声の始まり（-45 dBFS）→ ch2 で AI の声が最後に鳴った 10 ms 枠の終わり（その後 300 ms 静か）。語の境界の待ちとフェードを含む。スピーカーの出力遅延（outputLatency 約 32 ms）は含まない。
  - 内訳：検出（声の始まり → onset のイベント）、要求（onset → stop_requested）、境界（stop_requested → ch2 の無音）。ログの `stop_latency_ms`（VAP が推定した first_voiced_at → stopped_at）も並べる。
  - 偽マイクの入力は負荷で数百 ms 飛ぶことがあった（録音には欠落がないのに刺激とのずれが途中で 0.7 秒変わった）。刺激ごとに直前のずれ ±0.8 秒で録音の始まりを探し直す区分ごとの合わせ方にした（全刺激で位置が見つかった）。
  - VAP の遅れ：vap.state を出した時刻 − 推論の入力の末尾の音声の時刻（録音の対応表で写す）。

## 結果（描画なし、① 2 本・② 2 本、合成音声）

### 1. 止まるまでの遅れ（① の中身のある発言で、AI の話の途中に入れ、実際に止まったもの）
| | n | 中央値 | p90 | 最小〜最大 |
|---|---|---|---|---|
| 声の始まり → AI の音が止まる（録音） | 10 | **580 ms** | **949 ms** | 160〜1120 ms |
| 内訳：検出 | 10 | 343 ms | 723 ms | |
| 内訳：onset → 停止の要求 | 10 | 1 ms | 3 ms | |
| 内訳：要求 → 音が消える（語の境界とフェード） | 10 | 228 ms | 235 ms | |
| 参考：ログの stop_latency_ms | 10 | 446 ms | 535 ms | |

予算（中央値 < 600 ms、p90 < 1000 ms）を描画なしではぎりぎり満たした。ログの値は録音より約 130 ms 小さい（first_voiced_at が本当の声の始まりより遅い）。**研究の報告には録音の値を使うべき。**

- 誤った停止（声でない音・相づちで止めた）は描画なしでは **0 件**（13 件中）。2 体描画の 1 本でも 0 件（8 件中）。件数が少なく、率の推定には足りない。

- 受け止めは本人の声の終わりから中央値 1030 ms（p90 1073、最大 3085 ms）。統合前の試走（2 体描画）では 1 件 6.2 秒待った（1 対 1 の turn.allowed が p_now の減衰を待った）。

## 試みの全記録と重なりの中の検出（2026-11-15 追記）

対象は 43c98cb（本節の変更）。上の節 2 の止めそこねへの対応。

### 何を変えたか
- **試みの記録** `two_ai.interjection_attempt`（新しいイベント。両条件、話し合いの段）：本人が話し始めようとした試みを、止まったかどうかにかかわらず 1 回 1 行で残す。試み＝検出器の声の連続を 300 ms 未満の切れ目でつないだまとまり（`interjection.attempt.merge_gap_ms`）。開いている割り込みの中で始まった声（言い足し）はその割り込みの一部として数えない。100 ms 未満の onset なしの声は出さない。
  - 項目：始まりと終わり、声の長さ、AI の再生と重なった長さ、試みの始まりに話していた AI のターン（ai_id、turn_id、turn_kind、点）、そのターンが終わるまでの時間と終わり方、p_now／p_future／vad／mic の最大値、onset の規則と検出の遅れ、結びついた interjection_id と episode の結果。
  - 結果（outcome）：`stopped`（止めた）、`held`（AI が話していない間の onset）、`sub_threshold`（閾値に届かず＝言おうとしたが通らなかった）、**`ai_finished_self`**（重なっていた AI のターンが試みの始まりから 1500 ms 以内に自分で話し終えた。止めそこねとは別に数える。`self_finish_window_ms`）、`backchannel`、`non_speech`（episode が false_onset／onset_no_speech）、`logged_only`（②）、`abandoned`。
  - episode（`two_ai.interjection_episode`）の意味と出し方は変えていない。`sub_threshold` の `two_ai.interjection` も従来どおり出る。
  - 報告：`report:two_ai --coding` が `coding/coding_attempts.csv` を書く（`--blind` では書かない。結果の列から条件が分かるため）。要約の「4. 割り込み」に試みの数を出す。
- **重なりの中の検出**（`interjection.detector.overlap`。AI が再生している間だけ効く。**既定 `enabled: false`＝従来どおり**）：
  - 持続の経路（`sustain_ms` 700、`sustain_p_now_mean_min` 0.4）：声の連続が 700 ms 続き、連続の中の p_now_user の平均が 0.4 以上なら、p の閾値を見ずに onset（規則 `overlap_sustain`）。相づち・咳・息は 700 ms に届かない。AI の声のエコーで vad_user だけが上がる場合は、VAP が人の側の p_now を低く見るので平均の下限で落とす想定（**エコーのある条件では未検証**）。`mic_dbfs_min` で mic の音量の下限も課せる（既定 null）。
  - 閾値の差し替え（`p_now_user_min`／`p_future_user_min`、規則 `overlap_threshold`）：切り替えとして残したが、下の比べで誤った停止が増えたので使っていない。
  - 通常の経路（vad ≥ 0.5 が 200 ms、p_now ≥ 0.5 かつ p_future ≥ 0.5）は変えていない。

### 止めそこねの中身（改善の前のログを刺激ごとに見直した）
上の節 2 の 3 件の本当の止めそこね（残り 1.9〜4.3 秒）では、vad_user は 1.0 に張り付き、p_now_user は 0.35〜0.55 を上下し（届く tick もある）、**届かなかったのは主に p_future_user（0.25〜0.45）**だった。and の条件で同じ tick に両方が 0.5 を越えなかった。中身のある発言は vad が 1.4 秒以上続くのに対し、相づち・咳・息の vad の連続は 650 ms 程度以下だった。それで「長さ」で分ける持続の経路を選んだ。

### 方法
- `tools/two_ai_eval/run.ts --overlap off|sustain`（`sustain` は設定の写しで overlap を有効にする）。描画なし（`avatar_a=none&avatar_b=none`）、台本（test_double）、実 MaAI、ポート 3482／8808、①だけ。
- 種 101、103、401、402 で、各種について off → sustain の順に交互に 1 本ずつ（計 8 本、18:06〜19:13）。同じ機械で他のエージェントが動いていた（load average 2.6〜7.2）。VAP の遅れの p50 は全本 33〜38 ms。
- 集計は `analyze.ts` の `rates_on_spot`。① の話し合いの段で、AI の発話（受け止めを除く）の区間の中に入れた刺激について：
  - 止めそこねの率＝止まらなかった中身のある発言 ÷（中身のある発言 − AI が自分で話し終えたもの）。AI が自分で話し終えた＝試みの outcome が `ai_finished_self`（試みの記録が無い古いログは残り 1.5 秒未満）。
  - 誤った停止の率＝止めた相づち・咳・息 ÷ 入れた相づち・咳・息。
  - 止まるまでの遅れ＝録音での声の始まり → AI の声が消えるまで（節 1 と同じ）。
- 注意：同じ種でも、止めた位置で以後の流れがずれるので、2 つの条件で刺激が AI の話のどこに当たるかは同じではない。そこで、**改善の前の 4 本の VAP の値をそのまま検出器に流し直す比べ**（同じ音声、同じ VAP の出力で、判定だけを替える）も並べた。

改善の前の 4 本の VAP の値を流し直した比べ（AI の話の中の刺激、中身のある発言 39、相づち・咳・息 23）：

| 判定 | 発言を検出 | 相づち・咳・息で発火 |
|---|---|---|
| 従来（off） | 33／39（止めそこねの 6 件を検出できない） | 4／23（すべて通常の経路の相づち） |

- 持続の経路は、止めそこねを減らし、それ自体では誤った停止を増やさなかった（実測で 4 回の発火すべてが中身のある発言、流し直しでも 0 件の増加）。代わりに、それで止まる発言の遅れは 0.7〜1.2 秒と長い（もとは止まらなかったもの）。
- 実測の後の誤った停止の増加（2 → 6）は、6 件とも従来の経路によるもので、流れのずれと件数の少なさによる揺れとみる（強い息 2 件は p_now 0.9 台で従来の条件を満たした）。誤った停止の率そのものは、まだ推定できる件数ではない。
- 600 ms では相づちが届き始める（余裕は 100 ms 程度）。合成の相づちは 0.5〜0.6 秒で、人の「うんうん」はもっと長いことがある。
- 残った止めそこね 1 件は、負荷で VAP の更新が 200〜450 ms おきに間引かれ、fresh と stale を行き来して声の連続が数え直されたもの（出どころが替わると連続を数え直す仕様）。

### 初期値
**変えていない**（`overlap.enabled: false`）。合成音声・エコーなしでは根拠が出たが、(1) 持続の経路はエコー（スピーカーの音が mic に回る）に最も弱い経路で、平均の下限による対策をエコーのある条件で確かめていない、(2) 相づちとの余裕が 100 ms 程度で、人の声の相づちの長さで確かめていない。有効にするには、設定の `interjection.detector.overlap.enabled` を true にするだけでよい。実機（Windows の Chrome、スピーカー）で、相づちとエコーの誤った停止を確かめてから有効にすることを勧める。

### 限界
- 1 声の合成音声、エコーなし、件数が少ない（各 4 本）。率は参考値。遅れは CPU の負荷に敏感で、他の作業と並行して測った。
- 試みの区切り（300 ms の切れ目）と「自分で話し終えた」の窓（1500 ms）は研究上の定義で、設定で変えられる。
