## RESPOND（Lee et al., 2026、arXiv:2603.21682v2、プレプリント）

**扱うこと:** 2者会話で、聞き手が次の語境界で backchannel／turn claim／stay silent のどれを取るかを、文字起こしだけから3クラスで予測する。Qwen3-0.6B を LoRA で調整し、FiLM で2つのつまみ（`c_bc`、`c_tc`）を条件づける。入力は最長5秒の窓で、再学習なしで積極性を変えられる。評価はコーパス（MM-F2F、CANDOR）と6名の探索的パイロット。turn claim は割り込み、重なり、通常の交替をまとめた1クラス。

**今回と重なる点:**
- 話し終わる前の逐次 ASR から、AI が発話権を求めるかを判断する。
- 積極性を調整の対象にする。

**違う点（範囲の記録）:**
- 判断の入力は文字起こしの窓とつまみで、「言う内容の価値」や「今申し出る理由」を候補として明示的に評価する段は本文にない。Fig. 4 では turn overtaking の判定後に部分入力から音声を生成する形に見える（図の読み取り）。
- 発声前の合図、候補の更新や撤回は扱っていない。
- 音声の手がかりは使わない（著者が制約として挙げる）。今回は VAP と併用する。

**実装判断に効く知見:**
- ASR の遅れは自環境で 250〜500ms とある。逐次テキストに基づく判断は、その分だけ必ず遅れる。今回も `t_content_evidence` から測る（仕様 §5）。
- パイロットで、頻繁または時機の悪い turn claim は信頼を損ねたとの報告がある（N=6、順序固定、著者も検出力不足と明記）。既定を控えめに、という設計上の示唆にとどめる。仕様 §4 の「不要な発話希望がないことも正しい挙動」と同じ方向だが、今回の裏づけにはならない。
- 文中の backchannel は邪魔、文末は自然という声があった。吸気の時機を考える際の観察点にとどまり、吸気の結論は導けない。
- 著者は、重なりのある全二重の端から端までの評価を今後の課題としている。

## Jarvis（Oh, Hiraki, Li, Tsvetkov, Gollakota, 2026、arXiv:2610.07506v2）

**扱うこと:** Zoom の複数人会話に参加する音声エージェント。事前共有の文書と照らして、誤りや情報の欠けを検出し、当人たちの自己修正を待ってから介入する。話す場合は文書の文を引用する。入り方は「隙間を待って話す」と「挙手して許可を待つ」の2通り。評価は合成データ（CHI-180-proactive）と23名の実セッション。英語のみ。

**今回と重なる点:**
- LLM が内容上の理由で介入を判断する。
- 自己修正で候補を取り下げる（今回の `WITHDRAW` に相当）。
- 判定結果を決定的なコードで検証する（今回の `evidence_span` の実在確認に近い）。
- 発声前に発話希望を示し、許可で発声する（挙手。今回の吸気とは手段も意味も異なるが、構造は重なる）。
- 話し始めの許可の語句を検出する（今回の招待検出に相当）。

**違う点（範囲の記録）:**
- 複数人で、エージェントは二次的な参加者。今回は1対1。
- 判断の単位はターン（Silero の 500ms 無音で区切る）。今回は話の途中の逐次 ASR で、ターン数を数えられない。
- 介入の根拠は文書で検証できる事実の誤りと欠けに限る。今回は役割や関心に基づく質問や異議を含み、正解が決まらない。
- 合図は Zoom の挙手と画面表示という明示的な記号。今回は身体動作で、伝わるかは未検証（仕様 §13-4）。

### 自己修正を待つ閾値の実装（§3.2.3〜3.2.4）

**時間の閾値ではなく、ターン単位の持続カウントである。**

| 要素 | 内容 | 配備時の値 |
|---|---|---|
| 主張の台帳 | LLM が論点を短い名詞句にし、埋め込み類似度で既存の主張と照合。実行可能な検出で加算、非実行可能な報告でリセット、言及なしは不変 | `σ=0.6`（all-MiniLM-L6-v2） |
| ゲート | 持続カウント到達、未解決、クールダウン外、未発言の4条件。参加者は `τ−1` ターン直せる | `τ=2`（実験で 1 と 3 も）、`ρ=6` ターン |
| 自己修正の検査 | 毎ターン LLM が「解決済みか」を判定。ゲートの判定より前に適用 | 温度 0.1 |
| 決定的なガード | 直近3ターンに正しい値があり、内容語の 60% 以上が一致、数値は完全一致。質問や「思い出せない」は不可。主張を提起したターンにない語を含むこと | — |
| 忘却 | 閉じた主張と未言及の主張を一定ターンで破棄 | `W=10`、`W_r=3` |

著者は「待つ」と「修正の検出」を切り離せない1つの仕組みとして説明する。両方を外したアブレーションで沈黙が大きく減ったと報告している（合成データ）。

### 今回の判断に効く点（採用の決定ではなく検討材料）

1. **ターンの代わりの単位が要る。** 話の途中ではターン数を使えない。計画 §4.5 の「新規の安定テキスト量と経過時間」が代わりになりうるが、**自己修正の猶予としての明示的な待ちは計画にない**（`NEW` がすぐ合図のゲートへ進む）。合図のゲートに「`NEW` の後も一定の増分だけ持続を確認する」段を入れるかを、S の反例「途中の疑問を数秒後に本人が解消」で検討する価値がある。入れれば吸気は遅れるので、仕様 §5 の遅延と取消率の両方で評価する。
2. **`WITHDRAW` も LLM だけに任せない選択肢。** 計画 §4.5 は「解消したか」を次の LLM 実行に委ねる。Jarvis は LLM の判断をガードで再検査する。日本語で語の一致の代わりに何を使うかは未検討。
3. **言い換えで同一性が切れる失敗。** 著者は主張の言い換えによる照合失敗を見逃しの主因に挙げる。今回の `candidate_id` を E が管理し、照合用の一覧を G へ渡す方式はこの問題の形が異なるが、`KEEP`／`NEW` の取り違えとして同様の失敗がありうる。ログで確認する。
4. **許可待ちの間に内容が古くなる。** 実セッションで許可待ちの中央値は 6.5 秒、上位 10% は 50 秒超。参加者が同じ内容を先に述べた例（3 秒差の例を含む）、話題が移ってから答えた例が報告されている。60 秒で破棄する仕組みもある。計画 §4.6 には候補の期限切れと開始直前の許可の再評価があるが、期限の値は未定で、再評価の対象は許可である。§4.3 の「再生開始時の検証」も版と PCM の一致を見るもので、内容の陳腐化は見ない。`DEFERRED` からの開始前に最新の ASR で内容も確かめるかを検討する価値がある。
5. **合図そのものが情報になる。** 画面の保留回答を読んで参加者が先に言う例が報告されている。吸気は内容を示さないので同じ形では起きないが、合図が人の話し方を変えることは観察項目になる。
6. **招待の検出。** 文末に固定した正規表現で否定（"not yet"、"wait" など）を除外する。ASR で語句が分割されるので近接する断片を連結する。許可の検出後 400ms 待ち、新しい発話がなければ開始する。日本語の「どうぞ」に語句はそのまま使えないが、この3つの構造は E1 の招待検出で検討できる。
7. **隙間と割り込み。** 開始は VAD 無音 2.0 秒＋エネルギー低下 350ms、停止は 0.5 秒の継続発話（相槌で止めないため）。停止の遅れの中央値は 486ms。割り込まれた後は話した時間で再生し直し、続きから、破棄を分ける。VAP を使わない別の方式で、HRI 2025 と比較されたものではない。中断後の再開を設計するなら参考になる（`hri2025_mapping.md` の U-10）。

### 評価の読み方の注意

合成データは著者自身が作ったもので規則的。実セッションでは研究チームの1名が誤りを仕込み、条件は順序と交絡している（著者が明記）。数値を「LLM の自発的発話一般」の性能として読まない。
